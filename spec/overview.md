# doctidex 协议

状态：Draft
版本：`v1.0.0`

本文档定义 doctidex `v1.0.0`。本版本以普通目录、UTF-8 Markdown 和少量 YAML
元信息建立供人类、agent 与程序共同读取的目录树结构。

本文中的“必须”“不得”表示符合本版本所需满足的要求；“应”“不应”表示存在充分
理由时才可偏离的推荐；“可以”表示允许的选择。发布状态与版本号相互独立，Draft
不改变这些词的规范含义。

## 1. 目标与协议边界

doctidex 的目标是：

- 保持内容可由常规文件与 Markdown 工具直接读取、编辑、比较和传输；
- 为人类和 agent 提供稳定入口、分层导航和渐进式披露；
- 允许复用已有导航文档、外部内容和不能完全遵循本协议的材料；
- 用可观察结构表达读取与符合性事实，同时保持扩展空间。

协议只规定目录树的可观察结构、元信息语义、读取关系和符合性条件。协议不规定实现
如何创建、解析、校验、生成、更新、存储或同步目录树，也不规定 agent 或其他实现的
工作流、权限、写入边界或交付方式。

知识分类体系、存储服务、查询引擎和具体工具行为不属于本协议。实现可以提供这些
能力，但不得把实现特有行为解释为 doctidex 符合性要求。

### 1.1 版本号

doctidex 标准使用 `vMAJOR.MINOR.PATCH` 三段式版本号。`v` 是版本标识的一部分；
三段均为不带前导零的非负十进制整数，数值 `0` 除外。版本号不包含第四段、预发布
后缀或构建后缀；Draft 等发布状态单独表达。

`v1.0.0` 是首个稳定兼容基线。后续版本按以下规则升级：

| 版本段 | 升级条件 |
|---|---|
| `MAJOR` | 发生不兼容的规范变更，例如删除必需结构、改变既有结构的语义，或使原本符合的目录树不再符合。 |
| `MINOR` | 增加向后兼容的可选能力或放宽约束，同时保持既有符合目录树及其结构语义不变。 |
| `PATCH` | 只作不改变符合性集合和可观察语义的修订，例如纠正文句或消除不影响要求的歧义。 |

一次发布包含多类变更时，只升级影响最大的版本段，并将其右侧各段归零。已发布版本号
不得复用，已发布版本的协议内容不得原地改写。版本号描述整份标准，不是实现包版本、
目录内容版本或内部数据格式版本。本版本不要求目录树声明所遵循的标准版本。

## 2. 术语

- **doctidex 目录树**：以一个 doctidex 根目录为入口、按本协议组织和读取的目录结构。
- **根目录**：其 `index.md` 以 `doctidex.root: true` 标识的目录。
- **目录树名称**：根目录的非空目录名；它是本地名称，不是全局唯一标识。
- **索引文件**：文件名为 `index.md` 的目录入口文档。
- **变更记录**：文件名为 `log.md` 的可选历史文档。
- **索引范围**：一个索引文件负责建立阅读入口的目录范围。
- **负责索引**：对某个路径具有索引责任的最近祖先目录中的 `index.md`。
- **接管边界**：子目录中出现 `index.md` 时，该索引开始负责其所在目录范围的位置。
- **局部配置**：`index.md` 中按最近负责制生效的 doctidex 配置。
- **条目路径**：结构化条目 `path` 属性中的相对文件路径。
- **链接根目录**：解析 doctidex 文件路径 link 时作为 `/` 的含义和路径上界的当前
  doctidex 根目录。
- **根绝对路径**：以 `/` 开头、以链接根目录为起点的 doctidex 文件路径；它不是宿主
  文件系统绝对路径。
- **根内相对路径**：以 link 所在文档目录为起点、词法规范化后仍位于链接根目录内的
  文件路径。
- **边界目录**：由 `doctidex.boundary-set` 声明、进入或离开其子树时发生跨界的目录。
- **跨界 link**：其文件路径从当前根目录的路径视角跨越边界目录的 Markdown link。
- **结构化 link 注释**：与一个 Markdown link 关联、以 HTML 注释承载的 doctidex
  映射。
- **safe**：没有为内容声明 doctidex 强制规则例外的状态。
- **unsafe**：内容被显式声明为不能满足或不应承担 doctidex 严格要求的状态。
- **可达**：从负责索引出发，按第 7 节定义的 Markdown 文件路径 link 图可以到达。

safe 与 unsafe 只描述 doctidex 符合性例外。它们不表示来源可信、内容无害、允许
修改、具有特定所有权或已经过安全审查。

## 3. 目录与责任模型

一个 doctidex 目录树的最小结构是：

```text
<doctidex-root>/
├── index.md
├── log.md                 # 可选
├── <其他文件>
└── <子目录>/
    └── ...
```

根目录必须具有非空目录名并包含 `index.md`。目录树可以包含任意层级的普通文件与
子目录。除本协议保留的名称外，协议不限制普通内容的文件名和格式。

根目录下的 `.doctidex` 是协议保留目录。协议或明确的协议扩展可以在其中定义名称与
语义；普通内容不得为其中的名称赋予冲突含义。`v1.0.0` 不要求该目录或其中任何固定
子路径存在。

### 3.1 索引连续性

`index.md` 可以出现在任意子目录。一个子目录包含 `index.md` 时，从该子目录到根目录
的每一级目录都必须包含 `index.md`。因此，读者可以沿连续的索引层级到达任意下级
索引。

根 `index.md` 负责根目录范围。没有自身 `index.md` 的子目录由最近祖先索引递归负责。
子目录出现自身 `index.md` 时，该文件在子目录处接管责任，祖先索引只需建立通向该
子索引的阅读入口，不再负责其内部内容。

接管只由目录中实际存在的 `index.md` 决定。一个索引不因链接到其他导航文档而转移
责任；导航文档可以帮助它满足可达要求，但不成为负责索引。

### 3.2 最近负责制

`doctidex.boundary-set`、`doctidex.atomic-indexing` 和 `doctidex.unsafe` 都是局部
配置。每个索引只声明其索引范围内的条目。祖先索引中的局部配置不得作用于接管边界
内部；子索引必须自行声明其范围所需的配置。根索引不需要汇总下级索引的局部配置。

条目路径可以标识负责范围中任意深度的目标，但不得越过一个接管边界后再标识其内部
目标。条目恰好标识接管边界所在目录时，只描述从父范围观察到的该目录入口，不改变
子索引内部的配置。

该规则使读者只在进入子索引范围后才需要读取和理解其局部配置。

## 4. Markdown 与 frontmatter

索引文件和变更记录必须是可读取的 UTF-8 Markdown 文档。其他文件可以使用任意格式；
其他 Markdown 文档也可以使用 YAML frontmatter。

Frontmatter 位于文件开头，由两行 `---` 包围，内容必须是 YAML 映射。重复键无效。
所有 doctidex 配置必须位于顶层 `doctidex` 映射中。协议不在其他顶层字段中定义配置，
以避免与其他标准冲突。

顶层 `type` 是为与其他文档约定互操作而保留的类型标识；doctidex 语义始终由
`doctidex.type` 决定。未知顶层字段、未知 `doctidex` 字段和普通 Markdown 内容不因
未知而导致不符合，但不得改变本协议已定义字段的结构或语义。

### 4.1 `index.md` frontmatter

每个索引文件必须包含：

```yaml
---
type: index
doctidex:
  type: index
---
```

根索引还必须包含布尔值 `root: true`：

```yaml
---
type: index
doctidex:
  type: index
  root: true
---
```

非根索引可以省略 `root`，省略等同于 `false`。`root` 若存在必须是布尔值。索引可以
包含第 5 节定义的三个可选列表；列表省略等同于空列表。

### 4.2 `log.md` frontmatter

每个处于 safe 范围的变更记录必须包含：

```yaml
---
type: log
doctidex:
  type: log
---
```

## 5. 局部配置

三个局部配置都采用结构化条目列表：

```yaml
doctidex:
  type: index
  boundary-set:
    - path: external
  atomic-indexing:
    - path: generated
  unsafe:
    - path: vendor/original.md
```

每个字段必须是 YAML 列表。`v1.0.0` 中，每个列表项必须是只以相对路径标识目标的
YAML 映射，并且必须具有一个非空字符串属性 `path`。以 `/` 开头的路径不是相对路径，
不得作为条目路径。未知条目属性不具有 `v1.0.0` 语义，不得替代 `path`。

条目路径以声明它的 `index.md` 所在目录为基准。`.` 和 `..` 按路径段作词法规范化；
规范化过程不得移动到当前 doctidex 根目录的父目录。规范化结果必须能写成一个从根
目录出发且不含 `.` 或 `..` 的相对路径。规范化不得解析符号链接，不得依赖目标存在，
也不得以文件系统中目标的真实位置重写条目。`.` 可以标识声明索引所在目录本身。

条目路径只描述 doctidex 根目录视角下的词法位置。该位置上的 symlink、文件系统挂载
或虚拟映射可以指向根外物理内容，但其物理目标不改变条目仍位于当前根内的判断。

条目标识文件时，字段语义只作用于该文件；条目标识目录时，字段语义作用于该目录及
其子树，字段对目录内部的特殊规则除外。目标不存在时，声明仍具有路径语义；要求
条目标识文件或目录，是对该路径一旦出现时的目标种类约束。

同一列表中规范化后相同的路径等同于一个条目，不产生叠加语义；应删除这种重复声明。
不同列表可以标识同一路径，各字段语义同时生效，除非相应小节明确禁止该组合。

### 5.1 `doctidex.boundary-set`

`boundary-set` 的条目必须标识当前 doctidex 根目录内的目录。该目录子树与其根内
外部之间的路径边缘构成边界；link 从一侧到达另一侧时发生跨界。边界按当前根目录
视角下的词法路径形式判断，不解析符号链接的物理目标，也不要求边界目录或 link 目标
已经存在。

为判断 link 是否跨界，应：

1. 按第 8 节把 link 所在文档和 link 目标都表示为从当前根目录出发、不含 `.` 或
   `..` 的词法路径；无效或越出根目录的 link 不能参与边界判断；
2. 将当前负责范围内可见的边界条目规范化到同一个根目录路径视角；
3. 从 link 所在文档目录沿最短词法路径移动到目标：先返回两者的最近共同祖先，再进入
   目标路径；
4. 比较每次移动前后的位置是否分别位于某个边界目录子树的两侧；若是，该步跨越该
   边界；若跨越多个边界，以移动次序中的第一个为首次边界。

原始 link 中可消去的 `.` 和 `..` 不制造边界穿越。例如
`/external/../local.md` 在根内规范化为 `/local.md` 后再判断，不视为进入
`external`。进入边界时首次边界目录是移动后的目录；离开边界时是离开前所在子树的
边界目录。

边界条目本身不隐藏、不排除目标，也不自动把目标标为 unsafe。边界两侧的内容都可以
被读取和索引。外部物理目录树可以通过 symlink、文件系统挂载或虚拟映射呈现在根内
边界路径，再由普通根内 link 引用。边界只规定跨界事实、相应 link 元信息及符合性
判断；内容如何取得、映射、授权或同步不属于本协议。

### 5.2 `doctidex.atomic-indexing`

`atomic-indexing` 的条目必须标识目录。负责索引必须把该目录作为整体建立阅读入口，
但不必让其内部每个文件和子目录从负责索引递归可达。

被标记目录的 doctidex 元信息位于目录之外。该目录内部不得包含作为当前目录树协议
元文件的 `index.md` 或 `log.md`，也不得存在下级接管边界。读者仍可以使用普通文件、
搜索或链接工具读取内部内容；负责索引也可以选择性链接内部目标。

`atomic-indexing` 只改变索引粒度，不声明内容 unsafe，不建立读取限制，也不改变内部
Markdown link 适用的边界规则。无法满足这些规则的最小内部范围应另行声明 unsafe。

### 5.3 `doctidex.unsafe`

`unsafe` 可以标识文件或目录。它声明目标不能满足或不应承担当前目录树对其内容施加的
严格结构或 link 要求。unsafe 内容仍属于可读、可索引内容，也仍可参与可达性计算。

对 unsafe 目录不递归检查其内部内容的 frontmatter、索引连续性、日志连续性和 link
注释；对 unsafe 文件不检查该文件自身的相应内容规则。以下要求不因 unsafe 而免除：

- 声明 unsafe 的负责索引本身必须符合协议；
- `unsafe` 条目结构、相对路径和最近负责制必须有效；
- 负责索引仍必须建立通向 unsafe 文件或目录入口的可达路径；
- 指向 unsafe 路径的 safe 文档 link 必须按第 8 节显式声明 `unsafe: true`；
- `atomic-indexing` 对其目录内部协议元文件的禁止仍然有效。

unsafe 范围应尽可能紧。若干具体文件或更小目录足以覆盖已知不符合内容时，强烈不建议
只为减少条目数量而把包含无关 safe 内容的共同祖先整体标为 unsafe。过宽范围会减少
可严格检查、可依赖和可渐进披露的内容，降低目录树可用性，但本身不违反形式符合性。
unsafe 目录内部不存在反向恢复 safe 状态的声明；需要保持 safe 的内容必须留在 unsafe
范围之外。

`boundary-set` 与 `unsafe` 可以标识同一路径，表示该路径既是边界又具有符合性例外。
`atomic-indexing` 内部的具体文件或最小子目录也可以由外部负责索引标为 unsafe。

## 6. `index.md`

根索引是目录树的默认访问入口，也是唯一必需的协议文档。每个索引必须简要说明其
目录范围，并为人类和 agent 提供清晰的阅读入口。

索引必须使其负责范围内的每个文件和目录可达，但以下内容除外：

- 索引文件自身；
- 下级接管边界内部的内容，父索引只需使该子目录及其 `index.md` 可达；
- `atomic-indexing` 目录内部的内容，负责索引只需使该目录整体可达；
- unsafe 目录内部的内容，负责索引只需使该目录入口可达；
- 不存在的已声明路径。

索引不必直接枚举每个目标。它可以链接到 overview、README 或其他 Markdown 导航
文档，再由这些文档提供间接可达路径。协议不要求固定章节、列表形式或索引条目格式；
索引可以为发现效率直接重复关键入口。

索引应保持简洁，并在提供足够导航信息的前提下避免与已有权威导航重复。子目录具有
自身索引时，各级索引应按责任边界分层。

## 7. 可达性

可达性通过 Markdown 文件路径 link 构成的有向图计算。计算从负责 `index.md` 开始，
适用以下规则：

1. 标准 Markdown inline link、reference link，以及阅读环境明确支持且能解析为文件
   路径的 Markdown link 可以形成边；图片引用、普通文本路径和仅有 URL 的 link 不形成边。
2. link 目标必须是第 8 节规定的根绝对路径、根内相对路径或仅有 anchor 的形式，并且
   能解析为文件或目录路径。anchor 只定位目标内部位置，不改变目标文件；无法解析、
   越出链接根目录、不可读取或不存在的目标不形成边。
3. 目标是 Markdown 文档时，可以继续跟随其中的文件路径 link；目标是其他文件时，
   该文件可达但不继续展开；目标是目录时，该目录可达，但不隐式展开其内容。
   到达文件或下级目录也使路径上经过的祖先目录可达，但不会使这些祖先的其他内容
   自动可达。
4. 遇到下级 `index.md` 时，父范围的计算到该索引为止；子范围从该索引重新计算。
5. 符合第 8 节的跨界 link 可以形成边。通过根内边界路径呈现的 Markdown 导航可以
   继续形成边，也可以通过有效根内路径返回边界另一侧。
6. safe 和 unsafe 目标都可以形成边。来自 unsafe 文档的可解析文件路径 link 也可以
   形成边，但其缺少结构化注释不使该 unsafe 文档重新承担已豁免规则。
7. 计算必须记录已经访问的规范化路径；环路不会产生额外要求，也不得导致无限遍历。

同一物理文件通过不同词法路径到达时，协议不要求解析符号链接或证明物理身份。实现
可以报告这种情况，但符合性判断仍以当前根目录视角下的路径形式为准。

## 8. 文档 link 与结构化注释

doctidex 文档使用 Markdown 文件路径 link 导航。一个 doctidex 文件路径 link 的目标
由文件或目录路径加可选 anchor 组成，允许以下形式：

```markdown
[根绝对路径](/topics/reference.md#section)
[根内相对路径](../reference.md#section)
[当前文档内定位](#section)
```

以 `/` 开头的根绝对路径以当前 doctidex 根目录为基准，绝不表示宿主文件系统根目录。
根内相对路径以 link 所在文档的目录为基准。仅有 anchor 的目标等同于以当前文档为
文件路径的根内相对 link。anchor 是可选的文档内定位部分，不参与文件路径边界判断。

文件路径必须按路径段作词法规范化：

1. 根绝对路径从空的根目录路径栈开始；根内相对路径从 link 所在文档目录的根相对
   路径栈开始；
2. 空路径段和 `.` 不改变路径栈，普通路径段压入一层，`..` 弹出一层；
3. `..` 需要从空栈继续弹出时，路径已经越过 doctidex 根目录，该 link 无效；
4. 有效结果必须能写成从 doctidex 根目录出发且不含 `.` 或 `..` 的相对路径。

路径规范化和符合性判断不得解析 symlink、文件系统挂载或虚拟映射的物理目标。根内
词法路径对应的物理目标可以位于根外；这不改变 link 仍以 doctidex 根目录为路径上界。
反之，根外内容没有根内呈现路径时，不得通过 `../../external/...` 等越界形式直接
link，也不得把宿主文件系统绝对路径作为 doctidex link 使用。

内部 link 应优先使用相对路径；标准语法足够时，应优先使用标准 Markdown 形式。实现
可以支持成熟阅读器通用的 anchor 或 link 扩展，但扩展中的文件路径仍必须遵守本节
规则。其他不表示文件路径的 Markdown hyperlink 可以存在，但不是 doctidex 文件路径
link，不参与本协议的索引、可达性或路径符合性判断。

非跨界的 safe link 不需要 doctidex 注释。跨界或 unsafe 场景按以下各节处理。

### 8.1 结构化 link 注释

结构化 link 注释是附着于单个 Markdown link 的 doctidex 元信息容器。它使用一个
HTML 注释块，`doctidex:` 后的内容必须是 YAML flow mapping：

```markdown
[External](/external/guide.md)
<!-- doctidex: {cross-boundary-point: /external, unsafe: true} -->
```

映射不得包含重复键。`v1.0.0` 定义以下字段：

| 字段 | 类型、要求与默认值 | 语义 |
|---|---|---|
| `cross-boundary-point` | 非 `index.md` 的跨界 link 必需；路径字符串 | 标识从 link 起点到目标的词法路径上首次跨越的边界目录。 |
| `unsafe` | 可选布尔值，默认 `false` | `true` 表示 link 指向的路径为 unsafe；`false` 表示没有在此 link 声明例外。 |

`cross-boundary-point` 必须是非空的根绝对路径或根内相对路径，不得包含 anchor。
相对形式以 link 所在文档目录为基准；按本节路径规则规范化后，必须等于第 5.1 节
计算出的首次边界目录。它不必与 link 目标使用相同路径形式，但必须标识同一根内
词法路径。

未知注释字段不具有 `v1.0.0` 语义，但不得替代必需字段。一个 link 的关联序列中最多
只能有一个 doctidex 注释；多个 doctidex 注释会使该 link 的元信息无效。

### 8.2 注释关联与兼容性

在 Markdown 源文本中，一个 link 后可以出现连续的 HTML 注释块序列。link 与首个
注释块之间、相邻注释块之间可以只有空白；遇到首个既非空白也非完整 HTML 注释块的
内容时，关联序列结束。

doctidex 注释可以位于序列中的任意位置。序列可以同时包含其他标准或原文已有的
注释；这些注释不阻断关联，也不得因识别 doctidex 而被移动、删除、合并或赋予
doctidex 语义。为支持渐进读取，应把 doctidex 注释放在序列首位。

```markdown
[External](/external/guide.md)
<!-- another-standard: existing metadata -->
<!-- doctidex: {cross-boundary-point: /external} -->
<!-- original document note -->
```

### 8.3 必需性与省略

非 `index.md` 文档中的跨界 link 必须提供 `cross-boundary-point`。`index.md` 可以从
其有效 `boundary-set` 推导首次边界，因此不需要重复该字段；若索引仍提供该字段，
其值必须与推导结果一致。

任何 safe 文档链接到 unsafe 路径时，都必须提供 doctidex 注释并显式设置
`unsafe: true`，包括 `index.md`。`unsafe: false` 或字段缺省表示该 link 没有声明
例外，并不表示信任或安全结论。

只要当前场景有必需字段，或需要表达任一字段的非默认值，doctidex 注释就不得省略。
当所有适用字段都可缺省且都采用默认值时，整个注释可以省略；省略等同于各适用字段
分别取默认值。关联序列只包含其他注释而没有 doctidex 注释时，也按 doctidex 注释
省略处理。

注释无效或缺少必需字段时，该 link 仍是普通 Markdown link，但不能作为一条符合本
协议的跨界或 unsafe 阅读边参与 safe 内容的符合性与可达性证明。

## 9. `log.md`

`log.md` 是可选的变更记录，用于记录其所在目录范围内的重要变更。协议不要求目录树
必须具有变更记录，也不规定固定条目结构。

safe 范围内出现 `log.md` 时，从该目录到根目录的每一级目录都必须包含 `log.md`。
没有自身 `log.md` 的子目录由最近祖先变更记录递归覆盖；子目录出现自身变更记录时，
该记录接管其目录范围。`atomic-indexing` 目录内部不得创建变更记录，其变更由外部最近
祖先记录覆盖。unsafe 范围内部不承担日志连续性要求。

变更记录应按日期分组并按时间倒序排列，日期应使用 `YYYY-MM-DD` 格式。

日志描述可观察历史，不表示维护授权、写入范围或实现必须采用的记录过程。

## 10. 内容与扩展

Markdown 是文本知识的推荐格式，但不是其他内容的强制格式。除 safe 范围中的
`index.md` 和 `log.md` 外，协议不要求文档具有 frontmatter 或概念类型。

目录树可以包含自定义文件、目录、frontmatter 字段和 doctidex 扩展字段。未知内容
本身不影响符合性，但扩展不得占用本协议已定义的字段或保留名称并赋予冲突语义。

查询、知识抽取、缓存和其他场景化能力由实现决定。除非后续协议版本定义相应的可观察
结构或声明，这些工具能力不构成 doctidex 要求。

## 11. 符合性

一个目录树符合 doctidex `v1.0.0`，必须满足：

1. 根目录具有非空目录名，并包含可读取的 UTF-8 Markdown 文件 `index.md`；
2. 根索引具有 `type: index`、`doctidex.type: index` 和布尔值
   `doctidex.root: true`；
3. safe 范围内的 `index.md` 和 `log.md` 具有第 4 节规定的 frontmatter；
4. 索引与变更记录分别满足第 3.1 节和第 9 节的连续性；
5. 三个局部配置使用第 3.2 节和第 5 节规定的结构、根内路径与最近负责制；
6. `atomic-indexing` 目录满足第 5.2 节的整体索引和内部元文件限制；
7. unsafe 声明有效，且其入口仍按第 5.3 节可达并由 link 暴露；
8. 每个索引按第 6 节使其负责内容直接或间接可达，可达性按第 7 节计算；
9. 每个 doctidex 文件路径 link 使用当前 doctidex 根目录作为链接根目录，并满足第 8 节
   的根绝对路径、根内相对路径、词法规范化和 anchor 规则；
10. safe 文档中的跨界和 unsafe link 满足第 8 节的注释、字段和默认值规则；
11. 保留名称和扩展不与本协议已定义语义冲突。

unsafe 内容不因获得例外而成为 safe，但有效声明的 unsafe 内容不会单独使包含它的
目录树不符合协议。未声明的违反或无效的例外声明会使目录树不符合本版本。有效但过宽
的 unsafe 范围不构成形式违反，但按第 5.3 节受到强烈不建议。

除上述可观察要求外，其他内容与实现选择不影响 doctidex `v1.0.0` 符合性。
